# 科创50周线策略历史审计

归档日期：2026-10-03。

> 本文保留2026-10-02的原始研究结论；其中操作页面问题已在提交5f5c601修复。分段结果仅作为历史研究，不再展示在操作页面。“当前”一词指审计当时。

审计日期：2026-10-02。行情截止：2026-09-30。对象：`kc50-weekly` 的“三周深潜 · 大行情模式”v1.2。

**结论：核心想法值得继续研究，现有证据不足以证明它是一套可靠的实盘系统。回测可以复现，成本敏感性较低；但样本少、严格样本外证据缺失、参数及执行时点敏感，而且操作页面存在会反向误导动作的错误。当前适合冻结规则后进行前向模拟，尚未通过实盘验收。**

这不是当前买卖指令。页面持仓是历史模型推演，未连接用户实际账户。

规则的可执行定义如下：

1. 使用指数000688日线，按ISO自然周汇总；KDJ为9周最高/最低计算RSV，K、D依次以1/3权重平滑，初始化50，J=3K−2D。
2. 前三周J全部小于5，当前周J高于上一周，下一交易日开盘全仓买入。当前J不必超过5，价格不必已进入上升趋势。
3. 买入原始点位下方12%为固定保护止损；日内低点触价按保护价卖出，跳空跌破按开盘卖出，另扣卖出摩擦。
4. 标准模式退出实际要求“当前周J仍大于90，且比上一周低”，随后下一交易日开盘清仓。若上一周J>90而本周直接降到90以下，单凭这个条件不会卖出。文案需要把这一细节写清楚。
5. 最高完整周收盘达到买入原始点位的130%后，永久进入大行情模式；忽略J退出，完整周收盘跌到持仓最高周收盘的85%或以下才发出卖出指令。12%保护止损仍保留。
6. 每年最多6个买卖动作，买卖各算一次；买入时预留一次退出额度。低频不等于低风险，12%保护线也不是账户历史最大回撤上限。

经济假设是“连续深度超卖后出现动量改善，参与反弹；少数较强趋势延长持有”。这个假设说得通，但J只是价格派生指标，不能单独证明底部、估值便宜或未来上涨。这个系统仍是集中暴露于科创50单一风格的择时策略。

## 3. 证据的主要缺口

### 样本极少

9笔交易不足以可靠估计长期胜率、收益分布或尾部风险。7/9胜率的Wilson 95%区间约45.3%—93.7%；这个范围还假定交易近似独立，实际市场周期相关性会使解释更困难。两笔验证期胜利尤其不能支撑“稳定高胜率”。

2024-09-30至2026-03-23的一笔赚64.94%，约占全期对数净收益的42.3%。把这笔收益因子替换为1、其余保留的简单反事实仍累计约+97.75%，说明策略并非只靠这一笔才盈利；但验证期及大行情模式的证据明显集中。这种删除法不是重新运行完整交易路径。

### 严格样本外尚未建立

仓库首次保存这份v1.2代码的提交为`55cbc9b`，日期2026-07-29。未找到更早的参数冻结证据，因此不能直接将2024—2026历史称为严格样本外。

研究函数在54组参数中同时使用训练期和验证期胜率、年化，以及全期回撤参与评分，并以验证期交易数筛选；参见[研究评分逻辑](https://github.com/li-fujian/li-fujian.github.io/blob/03dc0da/kc50-weekly/scripts/build_strategy.py#L633)。如果用这个流程选参数，验证集就已参与选择。代码存在该流程，不足以断言作者实际运行过它或一定通过它选出了v1.2。

能够按仓库冻结时间检查的后续区间是7月29日至9月30日，账户日收盘估值收益−8.43%，新开1笔、尚未平仓。这个区间太短，既不能证明策略失效，也不能证明策略有效。该账户估值只扣已发生的买入成本，因此与假定期末卖出后的单笔−8.52%略有差异。

### 第一笔交易当时无法按所述系统交易

第一笔2020-04-27至2020-07-06赚26.53%，发生在指数正式实时发布之前。上交所公告明确：2020年7月22日收盘后发布历史行情，7月23日正式发布实时行情；首批科创50ETF于2020年11月16日上市。因此这笔只能作为回溯研究，不能算该交易工具当时可实现的交易。[指数发布公告](https://www.sse.com.cn/market/sseindex/diclosure/c/c_20200619_5130634.shtml)、[上交所ETF研究资料](https://etf.sse.com.cn/fundtrends/c/10055594/files/c41feab91f544352ac2782c4f24b0bb3.pdf)。

从ETF上市日2020-11-16重算，保留之前指数历史供指标预热、账户从现金开始，指数代理年化降为17.51%，累计157.77%，8笔已平仓。这仍是指数代理收益，不是ETF实盘收益。

## 4. 压力测试

以下都使用截至2026-09-30的同一数据，属于诊断，不用于再选择最优参数。

| 测试 | 年化收益 | 最大回撤 |
|---|---:|---:|
| 冻结参数，单边10bp | 19.16% | 18.54% |
| 单边20bp | 18.81% | 18.71% |
| 单边50bp | 17.76% | 19.19% |
| 单边100bp | 16.02% | 20.00% |
| 买卖信号执行再延后一个交易日 | 12.92% | 26.18% |
| 深度超卖要求2周，其余不变 | 12.25% | 34.15% |
| 深度超卖要求4周，其余不变 | 0.72% | 21.87% |
| 入场J阈值改0，其余不变 | 10.78% | 21.87% |
| 入场J阈值改10，其余不变 | 13.81% | 34.90% |
| 退出J阈值改80，其余不变 | 9.74% | 19.56% |
| 退出J阈值改100，其余不变 | 15.80% | 29.59% |
| 禁用大行情模式，保留标准退出 | 17.94% | 18.54% |

原研究范围54组参数为：入场J∈{0,5,10}、连续周数∈{2,3,4}、退出J∈{80,90,100}、止损∈{10%,12%}。年化最小−3.18%、中位数7.13%、最大19.16%；回撤中位数29.59%。当前组合正好位于该网格年化最高点。这是过拟合警示，不能单凭网格证明过拟合已发生；尤其连续周数是离散规则，会直接改变少量入场机会。

止损从6%、9%、12%、15%、18%变化，年化分别11.26%、12.95%、19.16%、17.94%、16.69%。6%止损仍出现19.14%账户回撤，说明单笔止损与账户峰谷回撤不可混用。

大行情模式30%启动、15%回撤的效果只有一笔已平仓大行情支撑。将启动改20%、回撤仍15%，年化13.94%、回撤28.15%；回撤改20%、启动仍30%，年化19.34%但回撤32.91%。关闭该模式后在场比例由47.4%降到33.7%，年化仅减少1.22个百分点，因此增加这段复杂逻辑的必要性仍需更多前向证据。

延迟测试的关键差异是：原本2024-09-30开盘782.31入场，延后一个交易日会跨过国庆假期，在2024-10-08开盘1045.05入场，随后止损。低频系统也可能高度依赖少数准确的执行时点，错过信号不能简单追买。延迟后的持仓、止损及后续信号都重新推演，并非只对原交易价格做固定扣减。

## 5. ETF执行与风控

原系统将指数同时当作信号和成交对象。投资者不能直接以000688指数点位买卖；需要先指定ETF、指数与ETF信号映射、保护线究竟由哪种价格触发，以及跟踪差异和费用口径。

诊断性模拟使用588000真实未复权OHLC，指数产生入场/J退出/大行情退出信号，ETF自身买入价设12%止损，T+1约束，单边10bp，从上市日开始：年化17.06%、回撤19.04%、8笔已平仓。它与同起点指数代理17.51%/18.54%接近，说明收益并非一换ETF便消失。

但这只是映射方案的初检：未复权序列未单独计入现金分红，未复核全部分红及订单价格调整，也未建模最小佣金、整手取整、盘口深度、集合竞价成交、涨跌停或条件单失效。不能将17.06%当成最终ETF总收益回测；不再重复扣已反映在基金市场价格中的管理费用。前复权接口本次只返回640根近期数据，不能直接替换为一个完整上市以来的复权数据集。

原回测允许买入当天日内卖出保护止损，而股票ETF实施T+1。[上交所ETF交易说明](https://www.sse.com.cn/assortment/fund/etf/question/c/c_20240118_5734755.shtml)。本样本9笔已平仓没有同日进出，补T+1后指数基准结果不变；这是未来风险场景的执行缺口，不能夸称它已造成历史收益高估。

周线看一次与日内止损只有在券商条件单可靠运行时才兼容。仓库没有实际下单或止损托管功能。−12%是原始成交价保护线，计成本后历史两次止损均为约−12.18%；跳空、停牌或无法成交时还可能更差。账户最大回撤18.54%为日收盘估值，未统计完整日内净值谷底，不能当作严格风险上界。

## 6. 已证实的操作页面问题

**高优先级：买卖状态不匹配。** [脚本](https://github.com/li-fujian/li-fujian.github.io/blob/03dc0da/kc50-weekly/scripts/build_strategy.py#L570)输出`BUY_NEXT_OPEN`和`SELL_NEXT_OPEN`，但[前端](https://github.com/li-fujian/li-fujian.github.io/blob/03dc0da/kc50-weekly/app.js#L24)仅识别`BUY`和`SELL`。抽取页面真实JavaScript函数并用Node执行，证实：

| 历史信号日期 | 脚本应显示 | 本周动作实际显示 |
|---|---|---|
| 2026-09-18 | 下个交易日开盘买入 | 不买，不猜，等信号 |
| 2026-03-20 | 下个交易日开盘卖出 | 继续持有 |

大标题由脚本直接填入，可能与本周动作同时冲突。该错误不改变Python历史回测数字，但用户依页面执行就无法实现那条净值曲线。

**完整周识别缺少交易所日历。** [实现](https://github.com/li-fujian/li-fujian.github.io/blob/03dc0da/kc50-weekly/scripts/build_strategy.py#L193)只按ISO周和星期五判断最后一周是否完整。9月30日已经是国庆前该自然周最后一个交易日，10月2日生成的数据仍将其标为形成中、最后完整周停在9月24日；官方10月1—7日休市。[上交所休市公告](https://www.sse.com.cn/disclosure/announcement/general/c/c_20260915_10832273.shtml)。本次不直接改变HOLD结论，但周中结束的假日周可能延迟发布信号。

历史回测却通过后续日线知道每个ISO周的最后交易日，于该日产生信号。实时页面必须到星期五或以后跨周更新才承认某些周完整，因此历史信号可用时间与页面更新规则并未完全一致。一般情况下可在下次开盘前赶上，但“只在周五打开一次”的用户未必能拿到同一信号，不能统一描述成周五收盘即可执行。

**未平仓显示成已卖出。** [交易表渲染](https://github.com/li-fujian/li-fujian.github.io/blob/03dc0da/kc50-weekly/app.js#L123)按`sell_date`有无判断是否卖出，但Python给未平仓交易也填了期末估值日期。当前未平仓9月21日交易因此卖出列显示9月30日。应按`status`区分真实卖出和估值。

**旧静态快照可回退成“当前决策”。** `index.html`静态内容停在2026-07-29，显示WAIT；正常加载JSON后是9月30日数据、HOLD。JSON失败时前端只记控制台错误、继续显示旧静态快照，没有醒目的过期阻断。页面模型也不记录用户是否实际成交，不能直接替代个人持仓台账。

## 7. 下一步验收标准

1. 先修买卖状态、未平仓显示和数据过期阻断；完整周与调度统一使用交易所日历。
2. 固定一个实际ETF和交易约定，补全现金分红、原始成交价、T+1、条件单执行及跳空压力场景，保持信号时间可审计。
3. 将2024—2026历史标为开发/回溯段，记录冻结日期；冻结后逐周保存当时可见数据、信号和实际/模拟成交，形成真正前向验证。
4. 以较简单的“深度超卖+标准退出+止损”为对照，同时冻结，比较新增大行情模式的风险收益贡献；不因为近期浮亏立刻调参数。
5. 补充按周期拆分、执行延迟、跨相似指数的预先指定规则检验，并考察持续持有、简单周线趋势规则及可接受账户风险。扩样本不能代替科创50自身的前向记录。

当前没有合理依据把19.16%当作未来年化目标，也没有足够证据要求放弃这套核心想法。更准确的定位是：**有吸引力的历史研究结果，尚未完成策略有效性与执行系统的双重验收。**
